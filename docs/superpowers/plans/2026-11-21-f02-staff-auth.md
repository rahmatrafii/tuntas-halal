# F02 Staff Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship the approved invitation-email authentication area with proven server sessions and active-membership authorization, preserving the dummy frontend.

**Architecture:** `/staf` bypasses the demo shell. Supabase SSR manages cookies; a small auth module validates login/confirmation and loads verified user memberships. Server Components, Actions, and the callback enforce their own checks. Tests run real Next/Auth/Mailpit locally with credentials in process memory.

**Tech Stack:** existing Next 16.4.6, React 19.3, TypeScript, Supabase SSR 0.12.7/supabase-js 2.119.1, CLI 3.2.0, Node test runner, jsdom, Docker.

**Spec:** `docs/superpowers/specs/2026-11-21-f02-staff-auth-design.md` (approved 21 November 2026).

## Global Constraints

- `/staf/login`, `/staf`, `/staf/akses-terbatas`, `/auth/confirm`; existing demo routes stay dummy.
- No cloud emails/invitations/test accounts, no app deployment or automatic commit/push.
- No public signup, tenant auto-selection, JWT implementation, generic CRUD framework, or new dependency.
- Use user identity plus active membership from the database, not demo state or user metadata. No shared auth cache.
- Preserve `.env.local`; local test server uses process overrides, fixed separate build directory and port.
- Mobile controls 48px, inputs 16px, existing monochrome tokens; explicit labels/error announcements.

## Review Focus

1. Unknown email vs provider transport failure must not enumerate accounts or claim a confirmed delivery.
2. Callback redirect/Host manipulation must not send cookies or users to an attacker origin.
3. Removing membership between requests must revoke the next protected response despite a valid JWT.
4. Cookie refresh/deletion and no-store headers must survive redirects and multi-cookie responses.
5. The auth test runner must use loopback endpoints and never expose tokens in child-server logs or cloud requests.
